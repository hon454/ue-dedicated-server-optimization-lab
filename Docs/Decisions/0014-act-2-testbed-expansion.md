# ADR-0014: 테스트베드를 한 번 확장하고(2막) 새 기준선에서 세 기법을 다시 적용한다

- 상태: 제안됨
- 날짜: 2026-10-03
- 출처: 2026-10-03 사용자 제안, [2막 설계](../Planning/2026-10-03-act-2-design.md), [ADR 목록](README.md)의 "ADR 이전의 결정", [ADR-0003](0003-lawless-baseline.md), [ADR-0007](0007-raise-send-limit-once.md)

## 맥락

포스팅 0\~4(1막)는 플레이어 캐릭터, 자원 노드, AI NPC 세 요소와 확정 규모(클라이언트 8, 자원 노드 5,000, NPC 300)에서 세 기법을 적용했다. 다음 포스팅들도 적용한 기법이 구별되는 변화를 보여야 하는데, 지금 테스트베드에는 재료가 부족하다.

- 세 기법 적용 뒤 서버 프레임 시간 평균이 13.16ms로 틱 예산 33.3ms의 40%다(`update-frequency3`).
- 남은 리플리케이션 시간 8.73ms의 95.0%가 `GameNetDriver` Exclusive 한 덩어리다([포스팅 4](../../Posts/04-update-frequency/README.md) "결과").
- Push Model, FastArray, `NetPriority`가 겨냥할 비용이 없다. Dormant 상태의 자원 노드는 `LabResourceNode` 타이머가 프레임당 0.007ms이고(`dormancy2-r2`), `out_bytes_per_sec_per_conn` 2,400은 엔진 기본 송신 한도의 2.4%다.
- 플레이어 자리 간격이 약 196m(2π × 500m ÷ 16)로 Net Cull Distance 150m보다 커서, 다른 플레이어의 캐릭터가 리플리케이트되지 않는다.

## 결정

1. **포스팅 0\~4를 1막, 포스팅 5부터를 2막으로 부른다.** 1막의 글, 태그, 수치는 그대로 둔다.
2. **테스트베드를 한 번 확장한다.** 네 요소를 함께 넣는다: 플레이어가 모이는 배치, NPC와 플레이어의 상태 값, 인벤토리, 건축물. 요소마다 실행 인자를 두고 기본값을 끔으로 해서, 인자 없는 실행이 1막의 시나리오를 재현하게 한다.
3. **1막의 세 기법을 실행 인자로 켜고 끌 수 있게 한다.** 인자 없는 실행은 세 기법이 모두 적용된 지금의 구성이다.
4. **새 기준선을 보정으로 정한다.** 클라이언트 수는 8로 둔다. 확정 조건은 1막의 네 조건에 하나를 더한다: 세 기법을 적용한 구성에서, 예정된 기법마다 겨냥할 비용이 `work_avg_ms`의 변동 폭보다 크다.
5. **새 기준선에서 세 기법을 약식으로 다시 적용한다.** 포스팅 5가 확장과 새 기준선을, 포스팅 6이 네 구성의 표와 1막과 달라진 점을 다룬다. 기법 없이 측정만 하는 포스팅(환경, 재적용, 진단)을 둘 수 있다.
6. **2막 동안 기준선을 다시 바꾸지 않는다.** 포스팅 7부터의 순서는 포스팅 6의 측정을 본 뒤 사용자가 정한다.

이 결정이 바꾸는 이전 결정이다.

- "ADR 이전의 결정"의 월드 구성(세 가지 요소)에 네 요소를 더한다. 세 요소는 그대로 남는다.
- STATUS.md "확정할 값"의 규모는 1막의 확정값으로 남고, 2막의 규모를 따로 확정한다.
- ADR-0007은 송신 한도를 한 번만 올려 고정한다고 했다. 2막의 기준선이 350,000바이트/초에 포화되면 같은 계산(기준선 송신량을 30Hz로 환산한 값의 약 두 배)으로 한 번 더 올려 2막 동안 고정한다. 1막의 한도와 수치는 그대로다.
- ADR-0003의 방식(기준선에서 엔진 기본 Relevancy 판정을 끈다)은 새 요소에도 그대로 적용한다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 지금 테스트베드로 계속한다 | Push Model, FastArray, `NetPriority`에 겨냥할 비용이 없고, 포스팅 4에서 이미 서버 프레임 시간 평균이 구별되지 않았다 |
| 요소를 그것을 다루는 포스팅에서 하나씩 넣는다 | 요소가 들어올 때마다 기준선이 바뀌고, 그때마다 세 기법을 다시 적용해 재야 앞 포스팅과 이어진다 |
| 요소는 그대로 두고 수만 늘린다(자원 노드, NPC) | 같은 비용 패턴만 커진다. 드물게 바뀌는 값, 배열, 밀집한 정적 액터, 플레이어 사이의 동기화는 생기지 않는다 |
| 건축물을 빼고 세 요소만 넣는다 | 구현은 줄지만, 나중에 넣으면 기준선을 한 번 더 바꿔야 한다 |

## 결과

- 2막의 수치는 1막의 수치와 직접 비교하지 않는다. 포스팅 6이 둘을 잇는다.
- 첫 측정 전에 요소 네 개와 전환 인자를 구현해야 한다. 태스크는 [2막 구현 계획](../Planning/2026-10-03-act-2-implementation-plan.md)에 있다.
- 인자를 모두 끈 실행이 1막의 수치와 구별되지 않는지는 측정으로 확인한다(구현 계획 태스크 16, 19).
- 겨냥할 비용이 있는 환경을 만드는 것까지가 이 결정의 범위다. 기법을 적용한 결과가 "구별되지 않음"이면 그대로 쓴다.
- `AGENTS.md`의 "포스팅 하나에 기법 하나", 루트 README의 포스팅 표(1막), backlog.md의 "우선순위 순"을 여기에 맞춘다.
