# ADR-0018: 포스팅 본문의 분량을 글자 수 2,500\~3,500자로 센다

- 상태: 대체됨 → [0019](0019-post-length-2000-to-4000.md)
- 날짜: 2026-10-06 (사용자 결정을 에이전트가 옮김)
- 출처: 태스크 25(포스팅 8 초안), 2026-10-06 사용자와의 논의. [ADR-0017](0017-post-length-range.md)을 대체한다

## 맥락

ADR-0017은 본문의 분량을 "표, 코드, 이미지, 링크 주소를 뺀 글로 6,000\~8,000자"로 정했다. 그 근거로 든 글의 수(약 6,600자, 7,800자, 7,900자)는 글자 수가 아니라 UTF-8 바이트 수였다. 포스팅 8 초안을 세다가 알았다(2026-10-06). 한글 한 글자는 UTF-8로 3바이트라서, 글자 수로 세면 값이 절반 아래로 준다.

같은 방법(표, 코드 블록, 이미지 줄을 빼고, 링크는 글자만 남기고 주소를 빼고, 줄바꿈을 빼고 공백은 센다)으로 지금까지의 본문을 다시 셌다.

글자 수 ÷ 바이트 수는 0.45\~0.47이다. ADR-0017의 범위 6,000\~8,000바이트를 글자 수로 옮기면 약 2,700\~3,700자다(6,000 × 0.45 = 2,700, 8,000 × 0.46 = 3,680).

## 결정

본문의 분량은 글자 수로 센다. 세는 대상은 ADR-0017과 같다: 표, 코드 블록, 이미지를 빼고, 링크는 보이는 글자만 센다. 공백은 세고 줄바꿈은 세지 않는다.

범위는 2,500\~3,500자다. 3,500자를 넘으면 수치와 단서를 측정 기록으로 옮긴다. 사용자가 바이트를 옮긴 값(2,700\~3,700자) 대신 기억하기 쉬운 값으로 정했다(2026-10-06). 독자가 3\~5분에 읽는다는 목표는 그대로다.

이 범위에서 테스트베드 글(2,360자)은 아래에, 포스팅 6(3,545자)과 포스팅 7(3,527자)은 위에 조금 벗어난다. 이미 쓴 글은 고치지 않는다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 2,700\~3,700자 | 에이전트가 낸 값이다. ADR-0017의 바이트 범위를 그대로 옮겨 같은 글이 범위에 든다. 사용자가 더 기억하기 쉬운 값을 골랐다 |
| 3,000\~4,000자 | 에이전트가 처음 추천한 값이다. 본보기 글(2,938자)과 기준선 글, 포스팅 4, 5가 범위 아래에 들어 글을 길게 쓰게 한다 |
| 단위만 "UTF-8 바이트"로 바꾸고 6,000\~8,000을 그대로 두기 | 숫자는 그대로지만 사람이 세기 어렵고, 같은 글도 영문과 코드 이름의 비율에 따라 값이 달라진다 |
| 그대로 두기 | 지침의 숫자와 실제로 세는 값이 두 배 넘게 달라서 지키지 않는 지침이 된다 |
