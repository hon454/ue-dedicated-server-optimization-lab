# ADR-0016: 서버와 클라이언트의 코어 고정을 Job 객체로 지킨다

- 상태: 승인됨
- 날짜: 2026-10-05 (사용자 승인)
- 출처: [engine-notes.md](../Reference/engine-notes.md) 마절, [ADR-0009](0009-server-cores-without-dpc-load.md), [ADR-0008](0008-reproducible-runs.md)

## 맥락

`run-scenario.ps1`은 서버를 논리 프로세서 2\~7(마스크 252), 클라이언트를 8 이상(마스크 4294967040)에 고정한다(ADR-0009). 프로세스 선호도는 실행 중에 전체 코어(4294967295)로 되돌아간다. 그래서 스크립트가 2초마다 다시 읽어 되돌아가 있으면 다시 설정하고, 측정 구간에 다시 설정한 실행은 실패로 처리한다.

이 실패가 2026-10-05에 확정 규모의 2막 기준선에서 일곱 번 연달아 났다(`act2-baseline2`, `3`, `5`, `7`, `8`, `9`, `10`의 `r1`. `4`와 `6`은 앞 실행의 프로세스가 남아 시작하지 않았다). 일곱 번 모두 측정 중에 되돌아간 것은 클라이언트였다. 그중 네 번은 PC를 건드리지 않은 상태였다. 2026-10-03 저녁에는 14회 중 4회였다.

원인은 엔진의 스레드 선호도 설정이다. `FRunnableThreadWin::SetThreadAffinity`는 `SetThreadGroupAffinity`로 그룹의 모든 코어를 요청한다(`Engine/Source/Runtime/Core/Private/Windows/WindowsRunnableThread.cpp:140-142`). 이 PC의 Windows(10.0.26300)에서 이 요청은 프로세스 마스크 밖이어도 성공하고, 그 순간 프로세스 선호도가 전체 코어로 넓어진다. 스크립트로 재현했다: 프로세스 선호도를 `FFFFFF00`으로 두고 새 스레드에서 `FFFFFFFF`를 요청하면 요청이 성공하고 프로세스 선호도가 `FFFFFFFF`가 된다. 스레드를 만들지 않는 프로세스는 40초 동안 되돌아가지 않았다. 클라이언트는 측정 중에도 스레드를 만들거나 선호도를 바꾸므로 언제든 되돌아갈 수 있다.

## 결정

`run-scenario.ps1`이 서버와 클라이언트를 띄운 직후 각 프로세스를 Job 객체에 넣고 `JOB_OBJECT_LIMIT_AFFINITY`로 같은 마스크를 건다(`Scripts/common.ps1`의 `Set-LabJobAffinity`). 마스크는 ADR-0009 그대로다. 기존의 2초마다 다시 설정하는 검사와 측정 중 재설정을 실패로 보는 규칙은 남긴다.

Job의 제한 안에서는 스레드가 마스크 밖을 요청하면 실패한다(오류 31). 스레드와 프로세스 모두 마스크에 머문다. 엔진은 `SetThreadAffinity failed` 경고 한 줄을 남기고 계속 돈다(같은 파일 143\~146줄). 작은 규모의 `tsmall-job1-r1`에서 재설정이 한 번도 없었고 종료 코드가 0이었다. 경고는 서버 로그에 9줄, 0번 클라이언트 로그에 36줄이었다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 지금처럼 실패한 실행을 새 라벨로 다시 재기 | 2026-10-05에 일곱 번 연달아 실패해 측정을 끝낼 수 없었다 |
| 측정 중 재설정을 서버에만 실패로 보기 | 클라이언트가 다음 검사까지 최대 2초 동안 서버의 코어 2\~7에서 돌 수 있다. 측정 조건이 느슨해진다 |
| 엔진의 `-processaffinity=` 인자 쓰기 | 0번부터 N개의 코어만 고를 수 있어(`WindowsPlatformProcess.cpp:135-182`) 2\~7이나 8 이상을 지정할 수 없다 |
| 게임 코드에서 스레드 선호도 설정을 막기 | 엔진 코드를 고쳐야 한다. 측정 환경의 문제는 스크립트에서 푼다(ADR-0012와 같은 이유) |

## 결과

- 마스크가 같으므로 지금까지 성공한 실행의 조건과 다르지 않다. 성공한 실행은 측정 구간에 재설정이 없었고, 그동안 모든 스레드가 마지막으로 설정한 프로세스 마스크 안에 있었다(`SetProcessAffinityMask`는 모든 스레드에 적용된다).
- 다른 점은 엔진이 스레드 선호도를 설정하지 못한다는 것이다. 엔진이 요청하는 선호도가 그룹의 모든 코어라면 실제 배치는 같다. 스레드마다 다른 코어를 요청하는 설정이 있는지는 확인하지 않았다.
- 2막 기준선 `act2-baseline1`은 Job 없이 쟀고, 포스팅 6의 네 구성은 Job으로 연달아 잰다. 비교는 Job으로 잰 묶음끼리 한다.
- `run-manual.ps1`은 선호도를 걸지 않으므로 바꾸지 않는다.
