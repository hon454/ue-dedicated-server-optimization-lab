# ADR-0017: 포스팅 본문의 분량을 세는 법과 범위를 정한다

- 상태: 대체됨 → [0018](0018-post-length-in-characters.md)
- 날짜: 2026-10-06 (사용자 결정을 에이전트가 옮김)
- 출처: 태스크 24(포스팅 7 초안), 2026-10-06 사용자와의 논의, [ADR-0015](0015-post-body-and-measurement-record.md)의 "결정" 4

## 맥락

ADR-0015는 본문을 "6,000자 안팎"으로 정했다. 무엇을 세는지는 정하지 않았다. 표, 코드, 이미지, 링크 주소를 뺀 글로 세면 그 뒤에 쓴 글은 모두 6,000자를 넘는다(2026-10-06).

| 글 | 표, 코드, 이미지, 링크 주소를 뺀 글자 수 |
| --- | ---: |
| [Relevancy와 Net Cull Distance](../../Posts/02-relevancy/README.md)(posting.md의 본보기) | 약 6,600자 |
| [1막의 세 최적화를 2막에 다시 적용](../../Posts/06-three-techniques-again/README.md) | 약 7,800자 |
| [네트워크 드라이버 자체 시간 나누기](../../Posts/07-net-driver-breakdown/README.md) 초안 | 약 7,900자 |

사용자는 포스팅 7 초안의 분량을 읽을 만하다고 판단했다. 2막 글은 확장 요소나 대조 실행을 설명하는 절이 하나씩 더 있어 1막 글보다 길다.

## 결정

본문의 분량은 표, 코드, 이미지, 링크 주소를 뺀 글로 센다. 범위는 6,000\~8,000자다. 8,000자를 넘으면 수치와 단서를 측정 기록으로 옮긴다.

독자가 3\~5분에 읽고 원리를 이해한다는 목표, 문장 규칙, 본문과 측정 기록의 구분은 ADR-0015 그대로다. 바뀌는 것은 ADR-0015 "결정" 4의 "본문은 6,000자 안팎이고" 한 구절이다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 6,000자 안팎을 그대로 두기 | 본보기 글도 넘는 수치라 지키지 않는 지침이 된다. 2막 글은 계속 넘는다 |
| 상한을 두지 않기 | 포스팅 0\~4가 길어서 다시 쓴 일(ADR-0015의 맥락)이 되풀이될 수 있다 |

## 결과

- [posting.md](../Guides/posting.md) "독자와 분량"과 [AGENTS.md](../../AGENTS.md)의 규칙 "포스팅은 독자가 3\~5분에 읽고 원리를 이해하게 쓴다"를 여기에 맞춘다.
- 이미 쓴 글은 고치지 않는다. 모두 8,000자 안이다.
