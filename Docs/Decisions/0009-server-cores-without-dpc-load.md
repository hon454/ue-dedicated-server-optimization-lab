# ADR-0009: 서버를 DPC 부하가 몰리는 코어를 뺀 논리 프로세서 2~7에 고정한다

- 상태: 승인됨
- 날짜: 2026-10-01 (사용자 승인)
- 출처: [engine-notes.md](../Planning/engine-notes.md) 사절, [ADR-0008](0008-reproducible-runs.md)의 "서버는 논리 프로세서 0~7" 항목

## 맥락

[ADR-0008](0008-reproducible-runs.md)은 서버를 논리 프로세서 0~7(선호도 마스크 `0xFF`)에 고정했다. 근거는 서버와 클라이언트가 같은 코어를 쓰지 않게 하는 것이었다.

규모 확정 단계에서 같은 구성의 실행이 세 배까지 달라졌다. 포화가 없는 두 성공 실행에서 `frames`가 100(`calib-b-r1`)과 293(`calib-e-r1`), `work_avg_ms`가 602.178과 204.726이다. 이 차이는 최적화 효과로 기대하는 크기와 같은 수준이라, 이대로는 3회 중앙값과 변동 폭으로 전후를 구별할 수 없다.

원인은 논리 프로세서 1번이다(engine-notes.md 사절). 시나리오가 도는 동안 1번에서 DPC가 초당 약 15,000개 처리되고 DPC 시간이 32~65%다(`diag-b-r1`). 서버 게임 스레드가 1번에 올라가 있으면 초당 0.20~0.49초의 CPU 시간만 받는다(`diag-a-r1`). 서버를 1번에만 고정하면 내내 느리고(`diag-c-r1`: `frames` 90, `work_avg_ms` 670.713), 2~7번에 고정하면 내내 빠르다(`diag-d-r1`: `frames` 340, `work_avg_ms` 176.630, `work_p99_ms` 216.841). `diag-c-r1`과 `diag-d-r1` 사이에 클라이언트 인자의 `-log`가 빠졌으므로, 같은 클라이언트 인자로 서버를 1번에만 고정해 다시 쟀다(`diag-e-r1`: `frames` 153, `work_avg_ms` 392.972). `diag-d-r1`의 2.2배다.

ADR-0008의 그 항목은 "0~7은 서버만 쓴다"는 전제에 기대는데, 실행 결과가 그 전제와 맞지 않는다.

## 결정

서버의 선호도 마스크를 `0xFC`(논리 프로세서 2~7, 물리 코어 3개와 그 SMT 짝)로 바꾼다. 클라이언트는 지금처럼 8~31에 둔다. 0번과 1번(같은 물리 코어)은 서버도 클라이언트도 쓰지 않는다.

ADR-0008의 나머지 항목은 그대로다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| `0xFF` 그대로 두고 3회 중앙값에 맡기기 | 변동 폭이 세 배라 ADR-0008의 판정 규칙으로는 대부분의 비교가 "구별하지 못했다"가 된다 |
| 1번만 빼기(`0xFD`) | 0번은 1번과 같은 물리 코어의 SMT 짝이라 1번의 DPC 부하에 영향을 받을 수 있다. 0번만 쓸 때의 속도는 재지 않았다 |
| 서버를 다른 물리 코어 묶음(예: 8~15)으로 옮기고 클라이언트를 나머지에 두기 | DPC가 몰리는 코어를 클라이언트가 쓰게 되어 클라이언트 쪽 흔들림이 생길 수 있다. 실행으로 확인한 구성은 `0xFC`뿐이다 |
| DPC를 만드는 드라이버를 찾아 인터럽트 선호도를 옮기기 | 시스템 설정을 바꿔야 하고 원인 장치를 아직 확인하지 않았다 |

## 결과

- `Scripts/run-scenario.ps1`의 `-ServerMask` 기본값을 252로 바꾼다. 승인 전에는 기본값이 255이고, 기준선과 그 뒤의 측정을 시작하지 않는다.
- 서버가 쓰는 논리 프로세서가 8개에서 6개로 준다. 리플리케이션은 게임 스레드 하나에서 돌므로 `diag-d-r1`에서 속도가 줄지 않았다.
- 어느 논리 프로세서에 DPC가 몰리는지는 이 PC의 현재 상태에서 확인한 것이다. 재부팅이나 드라이버 변경 뒤에 달라질 수 있다. 측정 전에 `\Processor Information(0,N)\% DPC Time`으로 2~7번이 0~2%인지 확인하는 절차를 포스팅 0의 측정 절차에 적는다.
- 승인되면 확정 규모로 한 번 더 실행해 기준선 조건을 다시 판단한다. `diag-d-r1`은 `-ServerMask 252`로 종료 코드 0, `saturated_ratio` 0.000, `over_budget_frames` 340 = `frames` 340이었다.
- 고정한 송신 한도 350,000은 바꾸지 않는다. 30Hz 환산 송신량이 상태와 무관하게 172,271~172,756이다.
- 포스팅 0의 "실행 방식"과 "한계"에 이 사실을 적는다.
